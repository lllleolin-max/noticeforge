# Actual artifact consumer and fair controls

`examples/pilot.py` creates an author-owned invoice application with calc/tax/money dependencies. Five setuptools source trees build five ordinary wheels; four are installed into a new application environment and their real `lab-invoice` entry point consumes CSV. Independent integer arithmetic checks the complete output. SBOM edges form a diamond and cycle, and leave the development component unreachable. The BOM and approvals bind exact generated wheel/material bytes.

The native consumer imports no NoticeForge modules. It uses a different fixed-point closure algorithm, reads original BOM/approvals, native ZIP entries and email metadata, then compares every component identity, artifact hash, expression, approved choice, material attribution, source/output path, full bytes, length and hash. It reads all bundle files and rejects missing or extra payloads. This is a consistency consumer, not an independent legal opinion. The pilot's approved branches are fixed authored lab decisions, not inferred policy.

Two controls use the same correct approved input and bytes: an independent manual collector materializes the declared materials after the human's policy decisions, and the actual registered NoticeForge CLI checks and stages them. Both pass the same native consumer. Three repeated runs alternate order. The manual collector runs in-process; the product includes CLI startup, validation, repeated hashing and fsync. This conservative comparison records the extra tool cost instead of hiding it. Build/preparation duration, approval/material decision counts, copy counts, full bytes and per-run timing are saved; no fabricated estimate of human approval time is made. A one-component small case is retained even when simple collection is faster.

Initial validation commands and generated outputs live in the separate implementation evidence directory. Source tests exercise expressions, cycle/diamond closures, source preservation, basename separation, aliases and byte bounds. Subsequent real review probes, defects and fixes are recorded in ITERATIONS after the complete initial baseline is committed. Until independently reviewed and published, no acceptance threshold or public CI result is claimed.
